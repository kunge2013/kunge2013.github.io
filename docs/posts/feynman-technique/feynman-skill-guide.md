## 什么是 feynman-learning Skill？

`feynman-learning` 是一个 Claude Code 的 Skill（技能插件），它让 AI 成为你的**费曼学习法教练**。

它不是直接给你答案，而是像一位经验丰富的老师，**通过图文引导**，带你走完费曼学习法的完整五步流程，帮你真正理解一个知识点，并能用通俗易懂的语言讲给别人听。

> 核心理念：**"学 = 教。教不出来 = 没学会。"**

## 使用流程

### 第一步：提出知识点

告诉 AI 你想学什么，越具体越好：

✅ **好的提问**：
- "用费曼学习法学习 TCP 三次握手"
- "帮我理解 Git 的 rebase 和 merge 的区别"
- "用简单话解释什么是区块链"

❌ **太模糊的提问**：
- "帮我学习计算机科学"（太大）
- "我想懂编程"（太泛）

### 第二步：跟着图文引导走

AI 教练会一步步引导你，每一步都有**可视化流程图**和**进度指示**：

```
学习进度：🎯 → 📚 → 🗣️ → 🔍 → ✨
          ✅    ✅    🔄    ⏳    ⏳
          
当前位置：🗣️ Step 3 - 输出教授
```

### 第三步：完成学习，获得成果

最终你会得到：
1. 📝 **通俗讲解稿**
2. 📓 **费曼笔记**
3. 📄 **可选：保存为博客文章**

## 五步详解

### Step 1 🎯：确立目标

```mermaid
flowchart LR
    A["用户提出<br/>知识点"] --> B{"概念是否<br/>足够具体?"}
    B -->|❌ 太大| C["拆解为<br/>更小的单元"]
    C --> B
    B -->|✅ 具体| D["确认学习目标<br/>和受众"]
    D --> E["激活前置知识<br/>已知什么?"]
    E --> F["📋 输出<br/>目标确认卡"]
    
    style A fill:#bbdefb
    style C fill:#ffccbc
    style F fill:#c8e6c9
```

**AI 会问你**：
1. 你为什么要学这个？
2. 你之前了解多少？
3. 最终讲给谁听？

### Step 2 📚：理解知识

```mermaid
flowchart TB
    subgraph INPUT["📥 输入"]
    I1["搜索资料"] --> I2["筛选来源"] --> I3["整理要点"]
    end
    
    subgraph PROCESS["🔄 处理"]
    P1["分类整理"] --> P2["思维导图"] --> P3["关联旧知"]
    end
    
    subgraph OUTPUT["📤 输出"]
    O1["呈现知识"] --> O2{"理解了吗?"}
    O2 -->|❌ 模糊| I1
    O2 -->|✅ 理解| NEXT["进入 Step 3"]
    end
    
    INPUT --> PROCESS --> OUTPUT
```

**AI 会帮你**：
- 搜索权威资料
- 画思维导图
- 整理知识结构
- 关联你已知的内容

### Step 3 🗣️：输出教授（最关键！）

```mermaid
flowchart TB
    START["设定场景<br/>给外行讲解"] --> USER["用户用自己的话<br/>解释知识点"]
    USER --> EVAL["AI 多维度评估"]
    
    EVAL --> C1{"🗣️ 通俗性"}
    EVAL --> C2{"✅ 准确性"}
    EVAL --> C3{"📋 完整性"}
    EVAL --> C4{"💡 类比"}
    EVAL --> C5{"📝 简洁性"}
    
    C1 --> RESULT{"综合评估"}
    C2 --> RESULT
    C3 --> RESULT
    C4 --> RESULT
    C5 --> RESULT
    
    RESULT -->|"✅ 全部通过"| PASS["Step 5"]
    RESULT -->|"❌ 有卡壳"| FAIL["Step 4"]
    
    style PASS fill:#c8e6c9
    style FAIL fill:#ffccbc
```

**评估维度**：

| 维度 | 检查要点 |
|------|----------|
| 🗣️ 通俗性 | 外行能听懂吗？ |
| ✅ 准确性 | 核心概念对吗？ |
| 📋 完整性 | 有遗漏关键吗？ |
| 💡 类比质量 | 类比恰当吗？ |
| 📝 简洁性 | 表达精炼吗？ |

### Step 4 🔍：回顾反思

```mermaid
flowchart TB
    START["汇总卡壳点"] --> ANALYZE["分析原因"]
    
    ANALYZE --> TYPE{"卡壳类型?"}
    
    TYPE -->|"记不住"| MEM["🔄 重新温习"]
    TYPE -->|"不理解"| UNDER["💡 换个角度"]
    TYPE -->|"知识欠缺"| FILL["📚 补充前置"]
    TYPE -->|"有争议"| VERIFY["🔎 搜索不同观点"]
    
    MEM --> RETRY["🔁 重新输出"]
    UNDER --> RETRY
    FILL --> RETRY
    VERIFY --> RETRY
    
    RETRY --> CHECK{"全部顺畅?"}
    CHECK -->|❌ 还有卡壳| ANALYZE
    CHECK -->|✅ 通过| NEXT["Step 5"]
```

║  核心理念：学 = 教。教不出来 = 没学会    ║
╚══════════════════════════════════════════╝

**对话过程**：

| 步骤 | 用户 | AI 教练 |
|------|------|---------|
| **Step 1** | 用费曼学习法学习递归 | 好的！问你几个问题：为什么学？了解多少？讲给谁？ |
| | 准备面试，知道函数调用自己 | 📋 目标确认卡生成 ✅ |
| **Step 2** | | 🧠 展示思维导图，梳理知识结构 |
| | 能理解 | ✅ 进入 Step 3 |
| **Step 3** | | 🎬 场景：面试官问"什么是递归？" |
| | 递归就像照镜子 | ⚠️ 卡壳：没提停止条件 |
| **Step 4** | | 🔍 分析：知识欠缺，补充基准情况 |
| | 递归就是拆小问题，但有停止条件 | 🎉 全部通过！ |
| **Step 5** | 用一句话总结？ | 递归就是把大问题拆成同样的小问题逐个解决，但必须知道什么时候拆到头了 |
| | | 📄 生成讲解稿 + 费曼笔记 |

**最终成果**：

```markdown
## 递归 - 通俗讲解

### 💡 一句话解释
递归就是把大问题拆成同样的小问题逐个解决，但必须知道什么时候拆到头了。

### 🎯 类比理解
像多米诺骨牌：一块推倒下一块，但最后一块推不倒时就停了。

### 📌 核心要点
1. 函数调用自身来解决问题
2. 必须有基准情况（停止条件）
3. 每次调用让问题规模变小

### ❓ 常见疑问
**Q**: 没有基准情况会怎样？
**A**: 无限循环，最终栈溢出报错。

### 🔧 实际应用
目录遍历、树形结构处理、分治算法等。
```
